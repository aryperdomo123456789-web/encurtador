# Shlink integration layer

This folder contains a small PHP-only integration layer for the Shlink REST API.
It is designed to be reused inside a panel like `me.vr766.com` without forcing a full framework setup.

## Files

- `ShlinkClient.php`
- `LinkProvisioner.php`
- `AnalyticsService.php`
- `DomainService.php`

## What the layer does

- Sends JSON requests to Shlink with `X-Api-Key` and `Accept: application/json`.
- Uses the official REST path format `/rest/v3/...`.
- Creates free links with:
  - random slug generated by Shlink
  - `validUntil` set to 7 days from creation
  - a monthly quota of 5 links per user
- Creates premium links with:
  - `customSlug`
  - no `validUntil` by default, so they behave as lifetime links
- Supports custom domains by registering the domain in Shlink before link creation.
- Reads visits and report-style analytics from the Shlink API.

## Official Shlink endpoints used

This layer follows the public Shlink API documentation and the OpenAPI spec.

- `POST /rest/v3/short-urls`
- `GET /rest/v3/short-urls/{shortCode}/visits`
- `DELETE /rest/v3/short-urls/{shortCode}/visits`
- `GET /rest/v3/visits`
- `GET /rest/v3/domains`
- `GET /rest/v3/domains/{domain}/visits`
- `POST /rest/v3/domains`
- `GET /rest/v3/tags/stats`
- `GET /rest/v3/tags/{tag}/visits`

If your Shlink instance exposes a different REST version segment, change the `apiVersion` argument when creating `ShlinkClient`.

## Error handling

`ShlinkClient` throws a typed exception when the API returns an error.
The message includes the HTTP status plus the Problem Details payload returned by Shlink when available.

Common mappings:

- `400` bad request or invalid payload
- `401` invalid API key
- `403` forbidden
- `404` not found
- `409` conflict
- `422` validation issue
- `429` rate limited
- `5xx` upstream or server-side failure

## Monthly free-link quota

`LinkProvisioner` does not depend on a framework or ORM.
Instead, it expects a tiny persistence contract:

```php
interface FreeLinkQuotaRepositoryInterface
{
    public function countFreeLinksForPeriod(string $userId, DateTimeInterface $from, DateTimeInterface $to): int;
    public function recordFreeLinkCreation(string $userId, array $record): void;
}
```

The implementation can live in Eloquent, Doctrine, raw SQL, Redis, or any other storage you already use.

Suggested storage rules:

- Count only free links.
- Use UTC month boundaries for the quota window.
- Store enough metadata to debug abuse later, like `shortCode`, `shortUrl`, `domain`, and `createdAt`.

## Example usage in Laravel

```php
use Vr766\Panel\Php\DomainService;
use Vr766\Panel\Php\LinkProvisioner;
use Vr766\Panel\Php\ShlinkClient;

$client = new ShlinkClient(
    baseUrl: env('SHLINK_BASE_URL', 'https://api-shlink.vr766.com'),
    apiKey: env('SHLINK_API_KEY'),
    apiVersion: 3
);

$domainService = new DomainService($client);
$domainService->ensureRegistered('links.customer.com');

$quotaRepository = new class implements \Vr766\Panel\Php\FreeLinkQuotaRepositoryInterface {
    public function countFreeLinksForPeriod(string $userId, \DateTimeInterface $from, \DateTimeInterface $to): int
    {
        // Replace with Eloquent or query builder logic.
        return 0;
    }

    public function recordFreeLinkCreation(string $userId, array $record): void
    {
        // Persist the audit row here.
    }
};

$provisioner = new LinkProvisioner($client, $quotaRepository, 5, $domainService);

$link = $provisioner->createFreeLink($userId, 'https://example.com/article');
$premium = $provisioner->createPremiumLink($userId, 'https://example.com/article', 'my-slug');
```

## Example usage in a Laravel service class

Bind the client and the provisioner in a service provider, then inject them where needed.

```php
app()->singleton(ShlinkClient::class, fn () => new ShlinkClient(
    env('SHLINK_BASE_URL', 'https://api-shlink.vr766.com'),
    env('SHLINK_API_KEY'),
));
```

Then keep your application logic thin:

```php
public function store(Request $request, LinkProvisioner $provisioner)
{
    return $provisioner->provision((string) $request->user()->id, $request->string('longUrl')->toString(), [
        'premium' => $request->boolean('premium'),
        'customSlug' => $request->input('customSlug'),
        'domain' => $request->input('domain'),
    ]);
}
```

## Example usage in Node

These PHP classes are not imported by Node directly.
For a Node backend, keep the same request contract and mirror the same rules:

- free link: omit `customSlug`, set `validUntil` to 7 days
- premium link: send `customSlug`
- custom domain: send `domain`
- enforce the same monthly quota before calling Shlink

If the panel stays in Node, you can either:

- reimplement the same logic in Node using the same payload shape, or
- expose these PHP services behind a small internal HTTP endpoint and call that endpoint from Node.

## Notes

- Shlink returns dates in ISO-8601 with offset.
- Shlink error responses use Problem Details JSON.
- The API key must be sent through `X-Api-Key`.
- If you are testing against a different Shlink version, verify the REST version segment before changing `apiVersion`.
